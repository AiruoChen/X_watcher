## 每次候选发布需绑定的证据

| 项目 | 来源 |
| --- | --- |
| 应用版本、源码哈希、锁文件哈希、提交、是否脏工作区 | dist/build-info.json |
| schema、配置 revision、模式、启动/停止会话 | data 卷 deployment-sessions；仅保留必要元数据 |
| Linux/Windows × Node 22.12/24 自动化结果 | CI offline-* 产物 |
| 镜像 ID、实际 Node、非 root/只读/隔离网络、强停/停止/重启/持久化 | CI linux-container-acceptance 产物 |
| 10 个模拟目标、10 万历史版本、耗时与查询计划 | acceptance:capacity 或 CI Linux/22.12 产物 |
| 合成时钟时效场景 | offline 报告 timing；不代表真实网络测量 |
| 真实模型质量、48 小时 preview、受控邮件与线上时效 | 后续受控外部验收；当前 not_run |

只从同一候选提交的 CI 获取证据，核对 sourceHash / lockHash 和配置。不得仅凭测试数量或一份旧 JSON 宣称新版本通过。产物不含真实邮箱、正文、密钥或个人路径；真实样本只能留在忽略的数据目录。

## 本地已运行的测量

- 2026-10-25，Windows / Node 22.12：324 项测试与 20 项场景映射通过；新增 19 项部署/健康/恢复/备份/证据用例。
- 合成时效：20 个样本，注入 60 秒分析等待，重置通知提交 P95=60000ms；日报场景入队偏移=0ms。这验证模拟流程和记录语义，未测量真实模型延迟或邮箱到达时间。
- NFR-09 本地实测：Windows 10.0.26200、Intel i9-12950HX、Node 22.12；10 个模拟目标 / 100000 历史版本，造数 3911ms、单日查询返回 24 条耗时 0.986ms、空待办查询 0.915ms，计划命中 posts_target_time。该次测量使用未提交候选，精确构建与原始结果留在忽略的 local-capacity.json；CI 为最终提交重新生成结果。单次测量不等同真实 X 流量性能保证。
- Docker Compose 在本机只做静态解析；本地守护进程未启动。Linux 容器实际结果以本候选 CI 产物为准，Windows 原生服务与其他架构未声明已验证。

## 真实发布门槛

- [ ] 选定并核验真实分析服务、模型和成本边界，完成至少 60 条评估。
- [ ] 确定公告召回率 ≥95%、精确率 ≥90%，虚构精确时间为 0；保留数据集与候选输出哈希。
- [ ] 同一构建、配置与运行会话至少 48 小时 preview；检查近期 48 小时各目标观察间隔。重启/换配置重新建立证据；长期会话只读取近期窗口，不累计无限历史。
- [ ] 来源无未解释覆盖缺口；RSSHub 的有限快照限制未被当作完整 V1。
- [ ] 真实邮件身份、幂等、未知结果核对及受控收件测试通过；accepted 不表示 delivered。
- [ ] 记录真实重置通知 P95 ≤2 分钟、健康日报 08:00–08:05 提交和实际成本，上游故障单列。
- [ ] 在目标主机完成停止、崩溃、备份恢复、升级和回滚演练，确认只有一个活动副本。
- [ ] 没有未解决事故、未核对发送或旧运行执行权。
- [ ] 实现并审阅真实 live 组合根后，才允许生产模式；本版没有该实现。

B09 代码和离线通过不能替代这些外部门槛。真实模型和邮件服务仍按之前的选择暂不指定，没有启动后台生产监测或发送邮件。
