# 日报、补报与历史补充（B07 / v0.8）

B07 提供业务编排、纯文本模板、本地状态/预览和持久化合同，全部以合成数据验证。真实 RSSHub、模型和邮件尚未联合验收；preview 运行依然只抓取，live 仍被拒绝。没有启动后台服务或发送邮件。

## 日期与完整性

默认北京时间 08:00 处理昨日 00:00（含）到今日 00:00（不含）。使用配置时区的自然日，夏令时一天可以是 23/25 小时；截止时刻遇到重复时钟采用第一次，缺失时钟采用随后第一个本地分钟。

常驻流程在 08:00 将必要补查合并到同一 ingest 任务，清空该次来源游标并固定重新读取的窗口，不另建网络定时器。只重读最近到期策略窗口，已有版本不重建分析作业。调度保留单调计时、并发领取、暂停与退避约束；系统时钟跳变不会绕过轮询等待。

报告同时要求完整的来源覆盖和到期后的成功补查证明。查询起止时刻保存在覆盖记录中，后续增量抓取不会抹掉此前证明。旧库的覆盖不包含补查证明，升级后需要下一次实际查询，不能直接推定完整。

上游必须能提供所需历史区间。Recent Search 历史限制、分页预算、来源故障或休眠过久可能使补查失败；这时保持 awaiting_data，不能伪造覆盖、跳过旧游标或自动回退计费 API。接受缺口/重设抓取起点等运维操作属于 B08。补报的 7 日上限不保证上游能提供这 7 个完整自然日。

## 状态和邮件

| 条件 | 结果 |
| --- | --- |
| 来源覆盖缺失或本轮补查未完成 | awaiting_data |
| 来源完整，分析仍滞后，未到 08:15 | awaiting_analysis |
| 08:15 仍缺来源（已记录等待，后续检查仍未恢复） | 每目标/日期一次服务异常通知，继续等待 |
| 来源恢复 | 一次恢复通知；报告按实际分析完整度生成 |
| 只有分析滞后，已过宽限期 | partial，已验证分析或带标注的原文摘录/链接 |
| 来源成功完整、零帖或仅明确删除条目 | empty，不创建空日报邮件 |
| 来源与分析完整 | ready |

报告正文区分产品和发布状态，保留重置原文时间、未知时区和可转换的北京时间。生成/入队时间写在正文，实际供应商接收/发送时间以邮件头与投递记录为准。作者的重置公告不能作为账户额度恢复证明。

## 补报与不可变快照

- 自动处理最近 7 个已到期日期，从早到晚；每轮最多新增 3 封报告类邮件，跨目标共用额度。事故通知也保守计入轮次额度，重置/更正通知始终保持原有投递优先级。
- 更早日期通过持久化 firstDay / beforeDay 区间标记 skipped_by_policy，避免长停机时逐日写入无限历史记录；已存在的报告与邮件保持原状。时间后退不缩小该区间。
- 已报告日期出现迟到、编辑、明确删除或分析补充时，到下一次日报时刻创建 addendum，链接原报告日期和上一版本；不修改旧邮件，不计为昨日新帖。昨日为空也可以单独产生历史补充。
- 不根据 RSS 条目消失推断删除。B07 消费持久化的明确删除版本，真实来源的删除发现能力仍取决于适配器。
- 每份新快照固定全部帖子版本、分析结果、内容哈希、正文、变更集合与父报告。渲染在事务外执行；提交在同一同步事务重读输入并校验检查点、覆盖、报告和分析版本，然后保存报告、进度和 outbox。竞争失败需重新读取和渲染，不能沿用旧快照。
- 通知沿用 B06 尝试/核对语义；unknown / needs_attention 不能因生成补报而重发旧通知。

## 本地操作

命令只读取指定的现有 SQLite 库，不实例化来源、模型或邮件客户端，不要求真实 API 密钥。缺库不会自动创建；老库打开时执行带有效备份的 schema 6 无损迁移。沿用根目录忽略的 .env 配置。

```powershell
npm run digest:status -- 2026-10-24
npm run digest:preview -- 2026-10-24
# RSSHub / 缺口数据必须显式选择部分预览
npm run digest:preview -- 2026-10-24 --partial
# 可选第二参数：配置中的 handle
npm run digest:preview -- 2026-10-24 thsottiaux --partial
# 将显式日期固定为本地报告；不创建邮件
npm run digest:generate -- 2026-10-24
npm run reporting:demo
```

status 仅显示日期、计数、覆盖/等待/跳过状态和报告 ID，不打印邮箱、正文或凭据。preview 不写入报告/进度/outbox，stdout 是明确请求的内容输出，可能包含原帖，不要提交到 Git。可用 shell 重定向自行导出；npm 包装会输出构建日志，需要纯文本时在 build 后直接运行 node 的 cli.js digest:preview 命令。

generate 允许人工生成超出自动 7 日窗口的日期，但仍要求完整来源覆盖；允许原文摘录并标注分析不足。它固定本地报告且不自动入队邮件，之后不会自动补发同一基础版本。来源不完整时请使用 --partial 预览，不允许人工把它标为完整日报。

## RSSHub 的明确边界

RSSHub 的有限时间线只有未验证观察覆盖。B07 可以通过显式 --partial 展示“已收集内容，可能遗漏”，保留未知正文和待分析状态；这不等于完整日报。当前不自动发送部分来源报告，也不在 source-only preview 中运行分析、生成日报或投递。后续自动部分邮件需先完成真实分析/邮件服务、覆盖策略和受控验收。

## 验证与接口

入口为 application/BuildReport、DueDigests、ReportTextRenderer；领域端口为 ReportingStore / ReportRenderer；MemoryStore 与 SqliteStore 共享快照校验规则。Schema 6 新增 source_observations、report_progress、report_boundaries，原报告表与旧快照保留。

reporting.test.ts 覆盖日期/夏令时、07:59/08:00/08:15、完整与缺口/零帖、原文降级、历史编辑/删除/补分析、重启 1/7/10 日、节流、并发 CAS、事务回滚、旧库迁移和离线 CLI。真实时效、送达率和模型语义质量尚未测量，属于后续受控联调与 B09 验收。
